#### 4레벨 AI 파이프라인

단순 ChatGPT 래퍼가 아닌, LLM과 규칙 엔진을 결합한 **증거 기반 적응형 면접 시스템**입니다.

```
사용자 답변 입력
    ↓
L1 Analyst (GPT-4o-mini, temp=0)
    → 답변에서 evidence 존재 여부만 탐지 (True/False)
    → {role: true, action: false, result: true, ...}
    ↓
L2 StateEngine (Pure Python 규칙 엔진)
    → UNKNOWN → PARTIAL → CLEAR 상태 전이
    → decide_action: continue / move_slot / finish
    ↓
L3 Planner (Lookup Table, 40+ 매핑)
    → missing evidence → 질문 의도 결정
    → frozenset(["result"]) → "결과 변화 확인"
    ↓
L4 Interviewer (GPT-4o, SSE Streaming)
    → 의도 + 맥락 → 자연스러운 한국어 질문 생성
    → 13,169건 실전 면접 기출 DB 기반 질문 재구성
```

**핵심 설계 원칙:** LLM은 '탐지'와 '생성'만 담당, **판단과 흐름 제어는 규칙 엔진**이 담당 → 일관성 + 비용 효율

#### Evidence-Driven State Machine

| 상태 | 설명 | 전이 조건 |
|------|------|-----------|
| **UNKNOWN** | 필수 evidence 없음 | 초기 상태 |
| **PARTIAL** | 일부 evidence 확인 | evidence 1건+ 감지 |
| **CLEAR** | 모든 필수 evidence 확인 | ALL required confirmed |

- `decide_action()`: max_turns 초과 → finish, 현재 슬롯 CLEAR → move_slot, 연속 2턴 새 evidence 없음 → move_slot
- **LLM 없이 순수 Python 규칙**으로 판단 → 일관성 보장 + 비용 절감

<details>
<summary><b>🔍 시스템 상세</b></summary>

#### Hybrid RAG 설계 (Vector 60% + BM25 40%)

단순 벡터 검색 또는 BM25만으로는 한계가 있어 **앙상블 기법**을 적용했습니다.

```
사용자 쿼리: "서초구에 가까운 지진 대피소"
         │
    ┌────┴────┐
    ▼         ▼
 Vector     BM25
 Search     Sparse
 (60%)      (40%)
    │         │
    └────┬────┘
         │ 앙상블
         ▼
  재정렬(Rerank)
  최종 결과 반환
```

| 검색 방식 | "서초 지진 대피소" | "가까운 피난처" |
|----------|:--:|:--:|
| Vector만 | 65점 | 75점 |
| BM25만 | 70점 | 45점 |
| **Hybrid** | **92점** | **88점** |

#### LangGraph Agent - 8가지 Intent 분류 + 7개 전문 Tool

```
사용자 쿼리 입력
    ↓
Intent Classifier (8가지 분류)
    ↓
Query Rewriter (정규화/확장)
    ↓
Tool Selector (적절한 도구 선택)
    ↓
Tool Executor (7개 Tool 실행)
    ├─ 위치 기반 대피소 검색 (Kakao Geocoding + Haversine)
    ├─ 대피소 개수 조회 (37개 지역 키워드 매핑)
    ├─ 수용인원 기반 검색 (자연어 숫자 파싱)
    ├─ 재난 가이드라인 검색 (40개 재난 키워드 표준화)
    ├─ 일반 지식 Q&A (RAG + LLM)
    ├─ 대피소명 검색 (정확/부분 매칭)
    └─ 위치+재난 통합 검색 (이중 검색 + 스코어 재정렬)
    ↓
Response Generator (텍스트 + 지도 + 경로)
```
